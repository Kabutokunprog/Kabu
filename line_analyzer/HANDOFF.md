### このアプリについて
`line_analyzer/` は「ふたりの記録帳」という、LINEのトーク履歴（数万行）を分析するアプリです。
このリポジトリの他のプログラム（株アプリなど）とは**完全に無関係な、独立したアプリ**です。
ブランチは `claude/line-conversation-analyzer-ehrmhh` です。

ユーザーの当初の要望:
1. トークン（AIの利用量）をできる限り少なくしたい
2. 一度読み込んだら、後日追加されたトークは差分だけ読み込みたい
3. 読み込んだ会話は本人だけが見られる秘密フォルダに保存したい
4. 「2026年の4−6月くらいを振り返って」「どこに行ったっけ？」「彼女の彼に対する愛情度合いは？満足度は？」など、自由に質問したい
5. 二人の隠語を学習し、性生活の満足度なども分かるようにしたい（露骨な表現ではなく「奥が好きそうだ」程度の婉曲な表現でよい）
6. 別アプリ「MedicationReminder」の記録（交渉・鈍痛など）と会話を組み合わせ、「会話×時間×体の記録」で分析したい
7. 最終的には自宅のMacBookで動かしたい

### 現在の作り（すでに完成している部分）
| ファイル | 役割 |
|---|---|
| `la.py` | 操作コマンドの入口（import / summarize / stats / ask / chat / health-import / correlate / glossary / report / cost / settings） |
| `config.py` | 設定と秘密フォルダ（`~/.line_analyzer_private/`、権限700、`LA_HOME` で変更可） |
| `line_parser.py` | LINEのエクスポートテキストを1通ずつに分解（iPhone/Android/旧PC形式、複数行、通話時間、スタンプ等） |
| `db.py` | SQLite（talk.db）。メッセージに一意のID（uid）を付け、差分だけを追加する |
| `stats.py` | AIを使わない月ごとの集計（件数、話しかけた側、返信速度、愛情表現・ネガ表現の頻度、通話、深夜、隠語の出現回数） |
| `summarize.py` | 月ごとのAI要約。会話を圧縮してから送る。要約は保存し、件数が変わった月だけ作り直す。長い月は分割してから統合する |
| `ask.py` | 質問文から期間とキーワードをAIを使わずに読み取り、「要約＋集計＋抜粋」だけをAIに渡して回答させる |
| `glossary.py` | 二人の言葉（隠語）の辞書。よく出る言葉を候補として拾い、AIに意味を推測させる |
| `health.py` | MedicationReminderなどのCSV/JSONを取り込み（列名は自動推測）、記録日の前・当日・後と会話を比べる |
| `llm.py` | **AIの呼び出しはこのファイルだけ**。設定 `backend`（ollama / claude）で切り替え。使用量はDBの usage テーブルに記録 |
| `search.py` | AIを使わないキーワード検索（`la.py search`） |

検証の状況:
- 架空のデータで、取り込み・差分追加・集計・比較・辞書・要約（AI部分は偽の応答に差し替え）・質問の流れが動くことは確認済みです。
- **本物のClaude APIへの呼び出しは一度も試していません**（クラウド環境にAPIキーが無かったため）。

## 進め方

### ステップ0：プライバシーの約束（最初に必ず守ること）
- ユーザーは「できれば全部オフラインがよい」と考えています。
- **本物のLINEファイルや取り込んだ会話の中身を、あなた（Claude Code）が勝手に開いたり表示したりしないでください。**
  あなたが読んだ内容はAnthropic社に送られるため、オフラインの方針に反します。
- 不具合を調べるときは、件数・日付の範囲・送信者名の一覧・読み取れなかった行の数など、**中身が分からない情報だけ**を使ってください。
  どうしても実際の行を見る必要があるときは、理由を説明し、ユーザーの許可を得てから、必要最小限の行だけを見てください。
- 会話データ・記録・分析結果は絶対にコミットしないでください（`line_analyzer/.gitignore` で対策済みですが、コミット前に `git status` で確認すること）。

### ステップ1：AIをどちらにするかを、ユーザーと一緒に決める（まだ決まっていません）
まずMacの性能を確認してください（中身ではないので見てよい情報です）:
```
uname -m            # arm64 なら Apple シリコン（M1以降）
sysctl hw.memsize   # メモリ量（バイト）
sw_vers             # macOSのバージョン
python3 --version   # 3.10以上が必要
```

そのうえで、次の3つの選択肢を**平易な言葉で**説明し、おすすめを1つ示してから、ユーザーに選んでもらってください。

| | A. Claude（クラウドAI） | B. Mac内のAI（Ollama等） | C. 両方を切り替え可能に |
|---|---|---|---|
| 会話が外に出るか | 圧縮した会話と要約がAnthropicに送られる | 一切出ない（完全オフライン） | 設定次第 |
| 料金 | 最初の要約で数ドル、質問1回で数セント | 0円 | 設定次第 |
| 読み取りの精度 | 高い（日本語のニュアンスや隠語に強い） | 下がる（特に隠語・皮肉・気持ちの機微） | 両方を比べられる |
| 必要なもの | APIキー | M1以降・メモリ16GB以上が目安。初回要約に数時間かかることがある | 両方 |

判断の手助けとして、次の「お試し比較」を提案してください:
1. 本物の会話を取り込み（ステップ3）、**1か月分だけ**をBで要約する。
2. ユーザーの許可が得られれば、同じ1か月をAでも要約する（数セントで済む）。
3. 2つの結果をユーザー自身に読み比べてもらい、どちらにするかを決めてもらう。
   ※ 結果を読み比べるのはユーザーです。あなたが要約の中身を読む必要はありません。

おすすめの考え方: ユーザーはオフラインを重視しているので、**C（切り替え可能にして、まずBで試す）**が無難です。
ただしメモリが16GB未満なら、Bは実用的でない可能性が高いので、正直にそう伝えてください。

### ステップ2：選ばれた方式を実装する
**B または C の場合（Mac内のAI）:**
- `llm.py` の `call()` の中で、設定 `backend`（`"claude"` / `"ollama"`）によって呼び出し先を切り替えてください。
  呼び出し側（summarize.py / ask.py / la.py）の変更は最小限にとどめます。
- `config.py` の `DEFAULT_SETTINGS` に `backend` と `ollama_model`、`ollama_url`（既定 `http://localhost:11434`）を追加します。
- Ollamaとの通信は、追加の部品を入れずにPython標準の `urllib` で `/api/chat` を呼んでください。JSONで返してほしい場面では `"format": "json"` を使えます。
- ローカルのAIは一度に読める量が少ないので、`backend=ollama` のときは `max_chars_per_chunk` を小さく（目安8000前後）し、`options.num_ctx` も合わせてください。
- 日本語が得意なモデルを、**その時点のOllamaの公開状況を確認したうえで**、Macのメモリ量に合うものから2〜3個候補として提案してください（モデル名を推測で決めつけないこと）。
- ローカルの場合、`summarize` の料金見積もりは「料金0円・処理時間の目安」の表示に変えてください。
- Ollamaのインストール（https://ollama.com からダウンロード）とモデルの取得（`ollama pull モデル名`）の手順を、ユーザーに分かりやすく案内してください。

**A または C の場合（Claude）:**
- ユーザーにAPIキー（https://console.anthropic.com/ で発行）を `export ANTHROPIC_API_KEY=...` で設定してもらいます（`~/.zshrc` に書いておくと便利）。キーを画面に表示したりファイルにコミットしたりしないこと。
- 本物のデータを送る前に、**架空のデータで1回だけ**実際に呼び出して、動作を確認してください（`llm.py` は fallbacks / output_config / cache_control を使っています。SDKのバージョンによってエラーが出たら直すこと）。
- モデルの既定は `claude-opus-5-5` です。費用を抑えたい場合は `settings --set model_summary=claude-haiku-5-5` で切り替えられます（モデルを変えるかどうかはユーザーが決めること）。

### ステップ3：オフラインのキーワード検索コマンドを追加する（どちらを選んでも実施）
- `python3 la.py search 鎌倉` のように入力すると、そのキーワードを含む会話を日付つきで一覧表示するコマンドを追加してください（AI不使用・無料）。
- `--from 2026-04 --to 2026-06` で期間を絞り込めるようにし、前後1〜2通の会話もあわせて表示します。
- 隠語辞書に登録された言葉で検索した場合は、その意味もあわせて表示します。
- 結果はユーザーのターミナルに表示するだけにしてください。あなたが結果を読む必要はありません。

### ステップ4：本物のデータで初めて動かす
```
cd リポジトリの場所
git pull
cd line_analyzer
python3 -m pip install -r requirements.txt   # Claudeを使う場合のみ必要
python3 la.py import ~/Downloads/トーク履歴.txt
python3 la.py stats
```
確認すること（中身を見ずに確認できる範囲で）:
- 読み込み件数が想像に近いか、期間（最初と最後の月）が正しいかを、ユーザーに見てもらう。
- 送信者が2人とも正しく認識されているか（`settings` で me_name / partner_name を確認）。
- 件数が明らかに少ない場合は、`line_parser.py` が読み取れていない行がある可能性があります。読み取れなかった行の**数と、行の形（例：「時刻の書き方が違う」）だけ**を調べる小さな診断を追加して原因を探してください。
- そのあと、選んだ方式で `summarize` → `ask` → `glossary suggest` の順に試します。

### ステップ5：MedicationReminderの記録を取り込む
- ユーザーにMedicationReminderから記録を書き出してもらい、**1行目（列の名前）だけ**を見せてもらってください。
- `health.py` の `COLUMN_HINTS` と `CATEGORY_WORDS` に、その列名や記録の種類名を追加して対応させます。
- `python3 la.py health-import ファイル` → `python3 la.py correlate` で動作を確認します。

### そのほかの注意点
- 隠語辞書を直したあと、過去の要約に反映するには `summarize --force` が必要です（全期間の作り直しになるので、料金や時間を先に伝えること）。
- 性生活についての分析は、露骨な描写をせず、穏やかで臨床的な表現にする方針です（`summarize.py` の system_prompt に記載済み）。この方針は変えないでください。
- このアプリは株アプリと同じリポジトリにあります。内容が非常に私的なため、**非公開の専用リポジトリへ移すこと**を、落ち着いたタイミングでユーザーに提案してください。
- 携帯からの利用は、データを外に出さない方針のため現時点では対象外です。ユーザーから希望があれば、家のWi-Fi内だけで使う方法などを改めて相談してください。
- 変更したらコミットして、`claude/line-conversation-analyzer-ehrmhh` ブランチにプッシュしてください。
